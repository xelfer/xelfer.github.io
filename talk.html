Live coach on Fargate

or: how I made AWS run my lunch break

Nick Triantafillou · AWS Meetup · Aug 6 2026

The problem

I'm training for the Sydney Marathon.

I want a coach in my ear during runs — real-time cues: pace, HR, cadence, milestones, "push".

Nike Run Club has voice coaching. Runna does. Garmin sort of does.
None of them coach my plan, using my HR ceiling, in my voice.

What already existed

Garmin watch → LiveTrack URL (Gmail) ↓ NAS (Python rules engine) ↓ HA Companion push → phone TTS → Shokz headphones

Home-lab pipeline. Works. Runs on my NAS in Wollongong.

Can it live on AWS instead?

Same code. Zero rewrite. One env-var flip.

The port

Garmin → LiveTrack email ↓ NAS launcher (Gmail poll) ↓ ecs.run_task() ← this is the whole change ↓ Fargate task (same Python container) ↓ polls LiveTrack every 30s Cues → HTTPS POST → Home Assistant (via Nabu Casa) ↓ Phone TTS → Shokz headphones

The container is identical to what runs on my NAS. Dockerfile is 10 lines.

~50 lines of CDK Python

class LiveCoachStack(Stack):
    def __init__(self, scope, id, **kwargs):
        super().__init__(scope, id, **kwargs)

        repo = ecr.Repository(self, "LiveCoachRepo", repository_name="live-coach")
        vpc = ec2.Vpc.from_lookup(self, "DefaultVpc", is_default=True)
        cluster = ecs.Cluster(self, "LiveCoachCluster", vpc=vpc)
        logs_grp = logs.LogGroup(self, "Logs", retention=logs.RetentionDays.ONE_WEEK)
        ha_token = ssm.StringParameter.from_secure_string_parameter_attributes(
            self, "HaToken", parameter_name="/live-coach/ha-token"
        )

        task = ecs.FargateTaskDefinition(self, "Task", cpu=256, memory_limit_mib=512)
        task.add_container("orchestrator",
            image=ecs.ContainerImage.from_ecr_repository(repo, "latest"),
            logging=ecs.LogDrivers.aws_logs(stream_prefix="orch", log_group=logs_grp),
            secrets={"HA_TOKEN": ecs.Secret.from_ssm_parameter(ha_token)},
        )

ECR + Fargate cluster + task def + IAM + logs + secret injection.

The toggle

BACKEND = os.environ.get("LIVECOACH_BACKEND", "local")

if BACKEND == "aws":
    ecs.run_task(cluster="live-coach", taskDefinition="live-coach",
                 launchType="FARGATE", overrides={...})
else:
    subprocess.Popen([python, orchestrator, "--url", livetrack_url])

One env var. Local NAS for testing, Fargate for the real thing.

Task-per-session

  • Fargate container spawns when a LiveTrack email arrives
  • Runs for exactly the duration of the run
  • Exits when Garmin closes the session
  • Zero idle infrastructure.
My backend didn't exist 20 seconds before it started coaching me.

What the port cost

Dockerfile: 10 lines CDK stack (Python): ~50 lines Launcher toggle: 30 lines (subprocess vs boto3) Time: ~1 afternoon Container code changed: zero

Half of the afternoon was installing Node 20 to get CDK v2 running.
The AWS part was the fast part.

Non-obvious lessons

  • Task-per-session > always-on for user-triggered ephemeral workloads. Runna's backend runs 24/7 to serve users. Mine literally doesn't exist most of the day.
  • Compute portability was free. Same Python, same requests library, same coaching rules. Container abstraction actually delivered.
  • Delivery was the hard problem. The interesting engineering was routing TTS past Spotify to Android's music stream on Bluetooth. AWS was easy in comparison.
  • Nabu Casa saved me a day. Public HA URL with token auth. Would have needed to expose HA via Pangolin/Traefik otherwise.
