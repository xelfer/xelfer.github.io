Live running coach

built on AWS — coached my lunch run today

Nick Triantafillou · AWS Meetup · Aug 6 2026

The problem

I'm training for the Sydney Marathon.

I want a coach in my ear during runs — real-time cues on pace, HR, cadence, milestones, "push through it."

Nike Run Club, Runna, Garmin all do a version of voice coaching.
None coach my plan, using my HR ceiling, in my voice.

What it does

  1. Watch pings Garmin → LiveTrack URL emailed to me
  2. System spots the email, spins up a coaching session
  3. Polls LiveTrack every 30s for fresh trackpoints
  4. Rules engine decides when to say something
  5. TTS to my phone → Bluetooth headphones, mid-run

Today it fired 5 real cues during my 6km lunch run — pace, HR ceiling, cadence, milestone, time check.

Architecture

Garmin watch → LiveTrack email (Gmail) ↓ Gmail poller (small daemon on my NAS) ↓ boto3 → ecs.run_task() ← Fargate task spawns per session ↓ Fargate container: polls LiveTrack, runs rules engine ↓ HTTPS POST → Home Assistant (via Nabu Casa public URL) ↓ Phone TTS → Shokz OpenRun Pro (bone-conduction BT)

AWS holds the coaching compute. Everything else is glue.

What AWS is doing

Fargate Runs the coaching container. 0.25 vCPU / 512MB. On-demand per session. ECR Hosts the container image (live-coach:latest, 139MB). SSM Parameter Store Injects the HA API token as a SecureString — never touches the image. CloudWatch Logs Every cue, every trackpoint poll, every session end. IAM Task role + execution role, minimal-privilege. Default VPC Public subnets, task assigned public IP for outbound calls.

Task-per-session

  • Fargate container spawns when a LiveTrack email arrives
  • Runs for exactly the duration of the run
  • Exits when Garmin closes the session
  • Zero idle infrastructure. My "backend" doesn't exist most of the day.
Task-per-session > always-on for user-triggered, ephemeral workloads.
Fargate's cold-start is fast enough that you can start a service when the user acts.

~50 lines of CDK Python

class LiveCoachStack(Stack):
    def __init__(self, scope, id, **kwargs):
        super().__init__(scope, id, **kwargs)

        repo = ecr.Repository(self, "LiveCoachRepo", repository_name="live-coach")
        vpc = ec2.Vpc.from_lookup(self, "DefaultVpc", is_default=True)
        cluster = ecs.Cluster(self, "LiveCoachCluster", vpc=vpc)
        logs_grp = logs.LogGroup(self, "Logs", retention=logs.RetentionDays.ONE_WEEK)
        ha_token = ssm.StringParameter.from_secure_string_parameter_attributes(
            self, "HaToken", parameter_name="/live-coach/ha-token"
        )

        task = ecs.FargateTaskDefinition(self, "Task", cpu=256, memory_limit_mib=512)
        task.add_container("orchestrator",
            image=ecs.ContainerImage.from_ecr_repository(repo, "latest"),
            logging=ecs.LogDrivers.aws_logs(stream_prefix="orch", log_group=logs_grp),
            secrets={"HA_TOKEN": ecs.Secret.from_ssm_parameter(ha_token)},
        )

Firing a session

import boto3

ecs = boto3.client("ecs", region_name="ap-southeast-2")
ecs.run_task(
    cluster="live-coach",
    taskDefinition="live-coach",
    launchType="FARGATE",
    networkConfiguration={"awsvpcConfiguration": {
        "subnets": [...], "assignPublicIp": "ENABLED"}},
    overrides={"containerOverrides": [{
        "name": "orchestrator",
        "command": ["--url", livetrack_url, "--target-km", "6"],
        "environment": [{"name": "HA_URL", "value": nabu_casa_url}],
    }]},
)

One function call. Container is running ~15s later. That's the whole handoff.

Non-obvious lessons

  • Task-per-session works. Fargate cold-start is fast enough that you don't need an always-on service to feel real-time. A ~20s spawn is invisible against a 45min run.
  • SSM Parameter Store > env vars for secrets. Injected at container start via task-def secrets: binding. Token never sits in the image or task definition JSON.
  • CloudWatch is enough observability for this shape of workload. Every task = one log stream = the whole story of the run.
  • The hard problem wasn't AWS. It was routing TTS past Spotify to Android's music stream on Bluetooth. Once that was solved, the cloud port was an afternoon.
